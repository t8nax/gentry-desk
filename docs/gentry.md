# Gentry для разработчика панели

Справка для разработчика Gentry Desk. Описывает, что такое Gentry, как его поставить и обновить, как поднять демо-стенд, как задача проходит свой путь и как панель работает с ядром через контракт. Внутреннее устройство ядра не описывается: для панели справочник — контракт и `gentry <команда> --help`.

Номера задач вида #50 — Issues репозитория ядра `t8nax/gentry`.

Сведения соответствуют Gentry из `main` на 09.10.2026, версия контракта 0. Пока выпуска нет, команды и поля меняются; при расхождении верно то, что выводит `gentry --help` и описывают схемы `contract/`.

## 1. Gentry в двух словах

Gentry организует работу ИИ-агента (Claude Code) над программным проектом. Агент ведёт задачу от взятия до закрытия по флоу — порядку работы, который задал оператор. Оператор участвует там, где без него нельзя: отвечает на вопросы, принимает решения, задаёт флоу. Правила обеспечивает программа: команда, нарушающая порядок, отказывает с причиной.

Gentry — один исполняемый файл на Go: `gentry`. Им пользуются три стороны:

- **оператор** — командами `gentry …` в терминале;
- **агент** — инструментами сервера `gentry mcp`, который подключает плагин Claude Code;
- **панель** — теми же командами с `--json` и журналом событий.

Данные разделены на три места:

| Место | Что в нём | Где лежит |
| --- | --- | --- |
| Знание проекта | общие для команды сведения о проекте | отдельный git-репозиторий проекта |
| Процесс оператора | флоу проектов, библиотека субагентов | git-репозиторий `~/.gentry/process`, общий для машин оператора |
| Состояние работы | задачи, их путь по флоу, шаги, заметки, решения оператора, пул копий, журнал событий | `~/.gentry/state/state.db` (SQLite), только эта машина |

Все три места изменяет только Gentry. Панель их файлы не читает и не пишет.

### Термины

| Термин | Что значит |
| --- | --- |
| Проект | код и знание, подключённые к Gentry; у проекта есть префикс номеров задач, например `SHOP` |
| Рабочая копия, пул | каталог с кодом, в котором ведётся задача; пул — копии проекта в реестре Gentry; одна копия — не более одной задачи |
| Флоу | порядок работы проекта: сценарии, этапы, фрагменты, субагенты |
| Сценарий | граф этапов для вида задач, например «Фича»; выбирается при взятии задачи |
| Этап, узел | шаг сценария с инструкцией, выходом и исполнителем; узел — место этапа в графе |
| Переход, возврат, круг | переход ведёт к следующему узлу; возврат — переход к пройденному узлу, ограничен пределом; круг — номер прохода этапа |
| Выход этапа | результат, которым агент закрывает этап: артефакт, результат или отрицательный результат |
| Шаг | пункт работы этапа; агент объявляет шаги и отмечает их выполненными или снимает |
| Решение оператора | ответ или указание оператора по задаче, записанное дословно; только добавляется |
| Заметка | то, что нужно учесть на следующих этапах; только добавляется |
| Артефакт | файл или ссылка, сохранённые у задачи, например план |
| Попытка | новое взятие отменённой задачи с тем же номером |
| Черновик | неприменённые правки флоу; действующими их делает `flow apply` после проверки |
| Снимок флоу | копия флоу, которую задача сохраняет при взятии и по которой идёт до конца |
| Источник записи | кто записал: `operator` или `agent`; Gentry определяет его сам по каналу вызова |

## 2. Что изменилось по сравнению с agents-kit-web

Главное отличие: у ядра появился интерфейс. Прежняя панель читала и писала файлы кита, вызывала его скрипты через `pwsh` и сама запускала `claude`. Новая панель работает только через команды `gentry … --json` и журнал событий; данных Gentry она не касается.

| В agents-kit-web | В Gentry | Как панель получает |
| --- | --- | --- |
| база знаний, `agents-kit.json` | знание проекта | `gentry project list` |
| `local/me.json`, копии машины | пул рабочих копий | `gentry worktree list` |
| память задачи `work/<машина>/<слаг>.md` | задача в `state.db` | `gentry task show`, `gentry stage show` |
| разделы «## Оператору», «ответ:» | решения оператора | `gentry task show --statement`; запись — `gentry operator record` |
| `flow/scenarios.md`, `flow/stages/*.md` | флоу в папке процесса: YAML и Markdown | `gentry flow show`, `flow diff`, `flow apply` |
| исполнители `agents/` | субагенты флоу и библиотеки | `gentry flow show`, `library apply` |
| `worktree-add.ps1` | `gentry worktree add` | та же команда |
| `claude --bg` + навык кита | драйвер сессий | `task run`, `task stop` — после [#37](https://github.com/t8nax/gentry/issues/37) |
| `backlog.md`, `tracker.md` | встроенный бэклог и трекеры | после [#14](https://github.com/t8nax/gentry/issues/14)–[#23](https://github.com/t8nax/gentry/issues/23) |
| опрос `/api/workspaces` раз в 3 с | журнал событий | `gentry events --after`; ожидание новых — после [#50](https://github.com/t8nax/gentry/issues/50) |
| прямая запись файлов и `git commit` | только команды ядра | нет команды — задача в `t8nax/gentry` |
| `base-check`, `link-state` | проверка установки | `gentry doctor` — после [#33](https://github.com/t8nax/gentry/issues/33) |
| Чудо-Юдо через `claude -p` | не переносится: панель не запускает `claude` | ИИ-помощник в формах — открытый вопрос |
| «Расход» | не переносится | — |

Что переносится почти без изменений: оформление (токены, темы, шапка, полоса разделов, модальные окна, скелетоны), таблица копий с бейджами состояний, окно ответа оператору, отрисовка схемы флоу. Данные для них теперь приходят из контракта.

## 3. Установка и обновление

Выпусков Gentry пока нет ([#30](https://github.com/t8nax/gentry/issues/30), [#31](https://github.com/t8nax/gentry/issues/31)), поэтому он собирается из исходников. Раздел изменится, когда появится установщик.

### Что нужно

- Go 1.27 или новее: `go version`;
- git;
- Claude Code (`claude` в `PATH`) — если нужно, чтобы задачи вёл агент; для стенда и разработки панели он не обязателен.

### Сборка и установка

Windows, PowerShell:

```powershell
git clone https://github.com/t8nax/gentry $HOME\src\gentry
cd $HOME\src\gentry
New-Item -ItemType Directory -Force $HOME\.gentry\bin | Out-Null
go build -o $HOME\.gentry\bin\gentry.exe ./cmd/gentry
```

Папку `~\.gentry\bin` нужно один раз добавить в `PATH` пользователя и открыть новый терминал:

```powershell
$p = [Environment]::GetEnvironmentVariable('Path', 'User')
[Environment]::SetEnvironmentVariable('Path', "$p;$HOME\.gentry\bin", 'User')
```

Linux и macOS:

```bash
git clone https://github.com/t8nax/gentry ~/src/gentry
cd ~/src/gentry
mkdir -p ~/.gentry/bin
go build -o ~/.gentry/bin/gentry ./cmd/gentry
echo 'export PATH="$HOME/.gentry/bin:$PATH"' >> ~/.bashrc   # или ~/.zshrc
```

Проверка:

```text
$ gentry version --json
{"contract":0,"gentry":"0.0.0-20261009103522-c4e505aeaf75","knowledge_format":1,"state_schema":8}
```

В версии `gentry` есть коммит, из которого собрана программа.

### Подключение к Claude Code

```bash
gentry setup claude
```

Команда собирает плагин Gentry в `~/.gentry/integrations/claude` и регистрирует его в Claude Code. Плагин даёт агенту сервер инструментов `gentry mcp`, хук запуска сессии и скиллы `working-on-task`, `canceling-task`, `editing-flow`. Плагин регистрируется для всех сессий Claude Code пользователя и действует со следующей сессии.

Выполняйте `setup` только **без** `GENTRY_HOME` (см. раздел 4): с ним плагин всех сессий переключился бы на папку стенда.

### Обновление

```bash
cd ~/src/gentry
git pull
go build -o ~/.gentry/bin/gentry.exe ./cmd/gentry   # на Linux и macOS — ~/.gentry/bin/gentry
gentry setup claude
gentry version
```

После обновления открытые сессии Claude Code работают на прежней версии сервера инструментов до перезапуска.

## 4. Папка данных и демо-стенд

### Папка данных

По умолчанию все данные Gentry лежат в `~/.gentry`:

| Папка | Что в ней |
| --- | --- |
| `bin/` | программа `gentry` |
| `process/` | процесс оператора: `process/<проект>/flow/` — флоу проекта |
| `state/` | `state.db` и файлы артефактов задач |
| `integrations/` | плагин для Claude Code |

Другую папку данных задаёт переменная `GENTRY_HOME`. Так работают стенд и тесты: каждая папка — отдельный, независимый Gentry со своими проектами и задачами. Для разработки панели и её тестов используйте только отдельную папку данных, а не `~/.gentry`.

### Демо-стенд

Скрипт `scripts/stand.sh` создаёт стенд с условным интернет-магазином. Нужны bash (на Windows — Git Bash), git и `gentry` в `PATH`; программу можно указать переменной `GENTRY`.

```bash
bash scripts/stand.sh ~/gentry-stand
export GENTRY_HOME=~/gentry-stand/home
gentry task list --all
```

На стенде:

| Что | Состояние |
| --- | --- |
| Проект `shop`, префикс `SHOP` | знание создано заново |
| Копии `shop/main`, `shop/wt-1`, `shop/wt-2` | `main` — основная, занята SHOP-1; остальные свободны |
| Сценарий «Фича» | План → Реализация → Ревью; с ревью — возврат на реализацию, не более 3 раз |
| SHOP-1 «Скидка в корзине» | в работе: ревью вернуло задачу, идёт второй круг реализации; есть план, решение оператора с вариантами и заметка |
| SHOP-2 «Оплата картой» | закрыта: сценарий пройден |
| SHOP-3 «Импорт каталога из CSV» | отменена оператором с обоснованием |
| Черновик флоу | с ошибкой: узел `deploy` ссылается на несуществующий этап |
| Журнал событий | 37 событий |

Скрипт не очищает папку: если она есть, он останавливается. Чтобы пересоздать стенд, удалите папку сами и запустите скрипт снова.

Шаги, выходы этапов, артефакты и закрытие задачи есть только у агента (раздел 5), поэтому скрипт вызывает их через сервер `gentry mcp` — так же, как Claude Code. Функция `agent` в скрипте показывает, как это сделать для своего случая.

## 5. Как задача проходит путь

### Кто что делает

| Действие | Оператор (CLI) | Агент (инструменты `gentry mcp`) |
| --- | --- | --- |
| Взять задачу, отменить её | да | да |
| Посмотреть задачи, задачу, этап, попытки, заметки | да | да |
| Записать решение оператора, добавить заметку | да | да, со слов оператора |
| Объявить шаги, отметить, снять | нет | да |
| Закрыть этап выходом, пропустить этап | нет | да |
| Сохранить артефакт | нет | да |
| Закрыть задачу | нет | да |
| Флоу, библиотека, процесс, проекты, копии | да | да |

Панель — канал оператора. Шагов, этапов, артефактов и закрытия задачи у неё нет, и вызывать `gentry mcp` ей нельзя.

### Как это выглядит в работе

1. Оператор берёт задачу: в терминале (`gentry task take`) или словами агенту в Claude Code — «возьми задачу …». Gentry резервирует рабочую копию, сохраняет название, постановку и снимок флоу и даёт номер `SHOP-1`.
2. Агент читает инструкцию текущего этапа, объявляет шаги, выполняет и отмечает их.
3. Когда все шаги выполнены или сняты, агент закрывает этап выходом. На развилке он выбирает переход и обоснование. Возврат сверх предела Gentry отклоняет, пока оператор не разрешит ещё один.
4. Вопросы оператору агент сейчас задаёт в разговоре, а ответ записывает решением оператора. Через Gentry вопросы пойдут после [#39](https://github.com/t8nax/gentry/issues/39) — тогда же появится состояние «ожидает оператора».
5. Пройдя сценарий, агент закрывает задачу, и копия освобождается. Оператор может отменить задачу в любой момент; отменённую задачу можно взять заново следующей попыткой.

Каждое изменение записывается в `state.db` вместе с событием журнала — по нему панель узнаёт об изменении.

## 6. Контракт

Контракт — JSON-схемы входа и выхода команд, событий и ошибок. Он общий для ядра и панели и лежит в пакете Go `github.com/t8nax/gentry/contract`:

- `contract/schemas/*.json`, `contract/schemas/events/*.json` — схемы;
- типы Go, сгенерированные из схем: `contract.TaskShow`, `contract.ErrorOutput`, `contract.Event` и другие;
- `contract.Schemas` — схемы, встроенные в пакет (`embed.FS`);
- `contract/codes.go` — коды выхода, коды ошибок и виды ошибок флоу.

Панель подключает пакет как зависимость нужной версии. Типы TypeScript генерируются из тех же схем. Каталог схем в кэше модулей показывает `go list -m -f '{{.Dir}}' github.com/t8nax/gentry` из модуля панели. Генератор выбирает разработчик панели.

### Вывод

- `--json` выводит в stdout ровно один объект JSON и перевод строки, UTF-8, поля в `snake_case`. Успешный результат выводится как есть, без обёртки.
- Код выхода: `0` — успех, `1` — команда не выполнена, `2` — неверная командная строка.
- Неизвестные поля нужно игнорировать: новые поля и команды — совместимое изменение.
- Время — в формате RFC 3339, обычно в UTC: `2026-10-09T13:16:27.714Z`. Встречается и местное время со смещением (`2026-10-09T16:20:24.5925837+03:00` в выводе `operator record`), поэтому разбирайте время с учётом смещения ([#58](https://github.com/t8nax/gentry/issues/58)).

### Ошибка

```text
$ gentry task show SHOP-9 --json            # код выхода 1
{"error":{"code":"task_not_found",
          "message":"Задача SHOP-9 не найдена.",
          "hint":"Посмотреть все задачи: gentry task list --all",
          "details":{"task":"SHOP-9"}}}
```

- `code` — постоянный машинный код; по нему панель решает, что показать и что делать.
- `message` и `hint` — текст для оператора на русском; разбирать его нельзя.
- `details` — сведения для решения; состав по коду описан в `contract/codes.go`.
- Перечень кодов открыт: неизвестный код панель показывает как общую ошибку с `message`.

### Ввод

Поля команды передаются одним объектом JSON в stdin: `--input -`. Панель передаёт поля только так — без флагов полей и без пользовательского текста в аргументах. Неизвестное поле во входе — ошибка `input_invalid`. Схемы входа — файлы `*-input.json`.

### Проект и задача

Без указания команды определяют проект и задачу по текущему каталогу. Панель всегда указывает их явно: номер задачи (`gentry task show SHOP-1`, `--task SHOP-1`) и `--project shop`. Без `--project` вне проекта `task list` и `worktree list` показывают все проекты машины.

### Версия

`gentry version --json` выводит версии Gentry, контракта (`contract`), формата знания и схемы состояния. Панель сверяет версию контракта при запуске; при неподдерживаемой работает только на чтение и называет, что обновить. До первого выпуска версия контракта — 0 и меняется свободно.

### Журнал событий

```text
$ gentry events --after 34
{"seq":35,"time":"2026-10-09T13:16:35.186Z","type":"task.closed","project":"shop","task":"SHOP-2",
 "data":{"attempt":1,"source":"agent","worktree":"C:\\Users\\dev\\gentry-stand\\shop\\wt-1"}}
{"seq":36,…,"type":"task.taken",…}
{"seq":37,…,"type":"task.cancelled",…}
```

- Строка на событие, с `--json` и без; `seq` растёт без пропусков. Команды нет в `gentry --help`: она служебная.
- `--after <seq>` выдаёт события после указанного номера и завершается. Панель хранит последний обработанный `seq` и продолжает с него, в том числе после перезапуска.
- Ожидания новых событий (`--follow`) пока нет ([#50](https://github.com/t8nax/gentry/issues/50)). До неё журнал нужно опрашивать.
- Изменение состояния и его событие записываются в одной транзакции. Событие об изменении процесса (флоу, библиотека, синхронизация) записывается после коммита в git и может потеряться, если `state.db` недоступна. Поэтому экран флоу при открытии перечитывает флоу, а не полагается только на события.
- Типы событий: `project.added`, `worktree.added`, `task.taken`, `task.closed`, `task.cancelled`, `step.added`, `step.done`, `step.dropped`, `stage.exited`, `stage.skipped`, `note.added`, `operator_decision.recorded`, `artifact.saved`, `flow.applied`, `flow.draft_discarded`, `library.applied`, `library.draft_discarded`, `process.synced`, `process.remote_set`. Данные каждого типа описаны в `contract/schemas/events/`.

## 8. Подводные камни

- **Панель, запущенная из Claude Code, записывает от имени агента.** Сейчас Gentry считает вызовом агента любую команду, у которой в окружении есть `CLAUDECODE` (в сессиях будущего драйвера — `GENTRY_SESSION`). Если запустить бэкенд панели из терминала Claude Code или из инструмента агента, решения и заметки из панели получат источник `agent`. Бэкенд панели должен вызывать `gentry` без этих переменных. Проверено на стенде.
- **Текстовый вывод — только для человека.** Его формулировки и колонки меняются; панель всегда использует `--json`.
- **`setup` и `GENTRY_HOME`.** `gentry setup claude` при заданном `GENTRY_HOME` переключил бы плагин всех сессий Claude Code на эту папку. Если плагин уже подключён из другой папки, `setup` откажет с кодом `plugin_elsewhere`. Стендам и тестам `setup` не нужен.
- **Пути — в формате ОС.** На Windows — с обратной косой чертой, в JSON — экранированной.
- **Артефакт — путь к файлу в папке данных.** `task show` даёт путь к копии файла артефакта, но команды чтения артефакта нет ([#59](https://github.com/t8nax/gentry/issues/59)).
- **Состояние «ожидает оператора»** (`waiting`) есть в контракте, но пока не наступает: появится вместе с вопросами через Gentry ([#39](https://github.com/t8nax/gentry/issues/39)).
- **Каждый вызов — отдельный процесс.** На Windows вызов занимает около 35–50 мс. Замер сделан только на Windows; на Linux и macOS его нужно повторить.
- **Служебные команды** `events`, `mcp`, `hook` не показаны в `gentry --help`.
